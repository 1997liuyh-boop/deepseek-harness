# Agent Note: 桌面悬浮球共享会话导航

Status: implemented

[English](2026-10-26-orb-shared-session-navigation.md) | 中文

## 问题

悬浮球按独立工作区筛选历史，包含旧会话，却排除了主窗口中的普通会话。两端各自选择会话，导致用户无法在悬浮球中查看主窗口正在进行的对话。

## 决策

主客户端发布可见会话目录和当前会话。目录排除归档、子代理及未选中的空白会话，名称和运行状态来自同一份客户端会话摘要。悬浮球切换历史时请求主客户端现有导航服务。两端保留同一个会话并渲染其现有事件流，不复制聊天记录。

桌面 IPC 在主窗口与悬浮球外层窗口间传递目录和导航请求。只有这两个窗口的主框架能够发布或请求切换。主客户端按可见目录验证目标会话。共享存储分区的环境仍可使用浏览器广播频道。桌面提交消息前等待共享目录就绪，避免主窗口加载期间创建另一份悬浮球会话。

## 考虑过的替代方案

**保留悬浮球独立历史。** 会话不一致的问题仍然存在，用户必须再次寻找主窗口对话。

**只使用 BroadcastChannel。** Chromium 会将悬浮球外层来源下的应用内嵌页面与主窗口划入不同存储分区，即使应用来源相同，广播仍无法到达桌面内嵌页面。

**复制聊天消息。** 会产生第二份记录所有者，在流式生成、停止或工具调用期间可能发生分歧。

## 影响

主窗口拥有会话选择权并需要保持可用。在悬浮球打开历史也会切换主窗口。已有模型和权限仍由会话管理。工作室引用指定已启用插件，通过现有 studio 工具执行，不另建项目会话。

验证覆盖目录筛选、名称与运行状态、双向切换、原生发送窗口校验、目录就绪前启动、空白会话复用、引用补全及卸载。Windows 桌面验收覆盖双向真实模型回复、运行中的增量文本和从悬浮球发起的工作室工具调用。会话持久化格式没有变化。
