# @deepseek-ai/dsh-llm-routing

[English](README.md) | 中文

## 概述

通过已有供应商适配器路由会话。在模型设置中选择直连或有序故障切换队列，并指定默认候选和恢复预算。凭据仍由各供应商管理。

<a id="use-this-package"></a>
## 使用此包

基础 bundle 挂载此服务。在会话中选择**跟随系统**使用默认候选；手动选择队列成员时从该成员开始，选择队列外模型则保持直连。直连模式不会自动更换供应商。

在会话中选择**聚合模式**，即可使用已配置队列，即使系统默认采用直连。此选择仅作用于当前会话，不修改系统设置。队列中存在候选时才提供这两个路由选项。

聚合模式在每轮开始时捕获队列。允许恢复的请求失败经过有限重试后尝试后续候选，成功候选继续服务本轮后续工具步骤。新一轮重新从所选或默认候选开始。设置变更影响后续轮次，停止或卸载会取消等待中的恢复。

会话含图片时，恢复会跳过明确不支持图片的候选：不向其发请求、不写切换记录，图片保持完整。若因跳过而用尽队列且失败属于瞬时类型（传输、超时、服务端、限流、空响应），路由从队首再走一遍，最多再走两遍且受恢复预算约束；持续失败时本轮以该真实原因结束，而不是末位候选的「无法处理图片」。设置页会标出支持图片的候选，队列中只有一个时给出提醒。

<a id="understand-the-implementation"></a>
## 理解实现

`agent/resolve-model` 在提示词组装前选择真实模型。恢复通过 `agent/request-error` 和持久化的 `llm/retry` 事件进行，重新组装提示词并执行步骤准备。聚合请求禁用供应商重试执行器，但仍允许专用上下文恢复。`llm/validate-input` 检查已准备适配器的同代能力，在输入投影前拒绝明确不支持的图片。失败的半截回答不会进入可用助手历史。

## 模型体验

### 供应商故障切换

#### 模型看到什么

真实候选接收自己的提示词、工具和可读历史。模型变更以 `model-selection` 通知进入历史，失败的半截输出和重试诊断不进入模型输入。

#### Token 影响

每个已尝试候选都可能产生供应商费用。重试事件自身不贡献 Token。

#### KV Cache 影响

更换供应商或模型可能使供应商缓存失效。原始日志保留真实供应商身份和失败尝试。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 只有明确分类的传输、额度、凭据、模型不可用及模态失败触发切换。无效用户输入和不兼容加密历史保持终止。恢复预算限制重试调度，每次请求的超时由适配器负责。标题生成等辅助功能保留各自固定路由。
